## C语言代码规范

自动排版规则见 [.clang-format](.clang-format)，本文仅列出需要人工遵守的补充约定。

### 文件与组织
- 源码使用 UTF-8。文件、目录名全部小写，单词间优先使用下划线，名称体现功能。
- 头文件必须有包含保护，按原规范使用 `__<FILE>_H_`；只放声明、类型定义等，不放函数体。
- 头文件按“文件注释、预处理部分、类型和函数声明”组织；源文件按“文件注释、头文件引用、数据及函数实现”组织。
- 头文件包含顺序为：对应头文件、C 标准库、其他库、项目内部头文件。各类内部顺序遵循项目约定。

### 人工补充的排版要求
- 相对独立的函数和 `if/switch/for/do/while` 等程序块前后，用空行与其他代码隔开。
- 独立说明注释放在对应代码紧邻上方，与前面的其他代码用空行隔开；注释与被说明代码之间不留空行。单条语句、结构体字段的注释也可放在右侧，不放在下方。
- `#include`、`#define` 不受列宽限制；确需保留宏的人工排版时，仅对必要范围使用 `clang-format off/on`。超长标识符等由人工检查。

### 命名
- 类型使用大驼峰，如 `SensorData`；变量、参数和结构体成员使用小写加下划线，如 `sample_count`。
- 常量使用 `k` 加大驼峰，如 `kDaysInAWeek`；宏和枚举值全部大写，单词间用下划线。
- 普通函数使用大小写混合名称；原文未明确首字母大小写，此处统一采用大驼峰，如 `ReadSensor`。取值、设值函数与变量名匹配，如 `get_count`、`set_count`。

### 注释
- 有效注释行占代码总行数至少 30%；空白行、空注释及未填写的模板行不算有效注释。建议使用中文注释。
- 文件开头说明文件名、负责人、创建日期、用途、修改日志、版权及法律信息；无相关内容填写“无”。
  ```c
  /**
   * @file 文件名
   * @author [原作者],Codex
   * @brief 简要功能说明
   * @date 创建日期
   * @copyright Copyright (c) 年份
   */
  ```
- 函数注释统一使用以下模板：
  - 必要的输入输出、空指针约束、内存所有权、性能及同步前提写入对应说明；定义处补充必要的实现要点。
    ```c
    /**
     * @authors [原作者],Codex
     * @brief 简要功能说明
     * @details (可选)详细说明
     * @param 参数名 参数说明,每个参数使用一条 `@param 参数名 说明`，无参数时省略 `@param`。
     * @return 返回值说明，无返回和类型为 `void` 时写 `@return 无`。
     * @note (可选)补充说明
     */
    ```
- 不足以自说明的数据结构、具有物理含义的变量/常量/宏，以及复杂、关键或不直观的实现必须注释；物理量说明含义和单位。
- 修改代码时说明改动方式和原因，同一位置只保留最新修改说明；临时或待完善代码使用 `TODO`。
- 生成的代码根据功能块要添加注释

### 宏、变量与表达式
- 表达式宏的各参数及整体表达式加完整括号；多语句宏用大括号包围，建议采用 `do { ... } while (0)`。
- 基本类型和指针在定义时初始化；数组、结构体、共用体在定义时或定义后立即初始化。
- 局部变量不得与全局变量同名；删除未使用的全局变量，优先使用局部变量，模块私有全局变量使用 `static`，仅必要时使用 `extern`。
- 除简单赋值外，用括号明确复合表达式的运算顺序。不得使用含义不明的数字；物理状态和物理量使用有意义的宏或枚举，必须直接使用数字时说明含义。

### 控制语句与函数
- 浮点数不得直接用 `==`、`!=` 与数字比较，应按业务精度采用容差或范围比较；指针判空使用 `NULL`。建议条件比较中常量在前。
- 不在 `for` 循环体内修改循环变量；`switch` 必须有实际处理的 `default` 分支，确需省略时注明原因。
- 函数参数写明类型和名称；建议无参数函数写 `void`。输入参数在前、输出参数在后；结构体参数传指针。
- 函数保持简短、职责清晰；可重入函数使用共享状态或 `static` 局部变量时必须处理同步问题。
- 中断处理程序不得调用耗时、阻塞或不符合中断上下文要求的函数，如打印、阻塞等待、动态内存分配等。

### 内存与维护
- 动态内存申请后立即检查是否为 `NULL`；申请成功后、读取前完成初始化。确保各执行路径正确释放内存。
- `free` 后立即将对应指针设为 `NULL`，同时防止其他引用继续访问已释放内存。
- 建议调试输出统一格式，包含模块名或文件名及行号；处理编译器警告。修改旧代码时保持局部风格一致，既有不合规范代码可按项目约定逐步整理。
