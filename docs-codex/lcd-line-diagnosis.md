# LCD左上角横线排查记录

日期：2026-10-13。用户观察：开机纯蓝画面左上角有黑色横线，白色画面的相同异常呈黄色。

## 当前判断

这两种颜色变化都符合蓝色分量缺失：RGB565的蓝色0x001f清掉低五位变成0x0000黑色，白色0xffff清掉同样低五位变成0xffe0黄色。这是颜色特征推断，不能单凭它确认LCD面板故障。

开机纯色来自LcdFill，绕过LVGL、相机帧、标题和快门反馈。代码将每个RGB565拆成大端两字节，覆盖320×240像素；六个40行条带的窗口分别从0、40、80、120、160、200行开始，右下坐标采用排除边界。ST7789配置为RGB565、RGB顺序、大端、横屏swap_xy及mirror，SDK驱动发送正确的窗口结束减一参数。

## 已完成的对照

1. LCD时钟从原配置60MHz临时降为20MHz；正常默认值仍为60MHz，可通过menuconfig中的BOX3_LCD_SPI_HZ调整。官方说明该参数必须不超过面板规格允许范围，见[Espressif SPI LCD文档](https://docs.espressif.com/projects/esp-idf/en/v5.5.2/esp32s3/api-reference/peripherals/lcd/spi_lcd.html)。这里不据此断言原60MHz一定超规格。
2. 当前源码添加可保持纯色的诊断控制，大写B/W/R/G/K为蓝/白/红/绿/黑，X切换180度面板方向，b或实体K2长按退出；只可从没有录像和待拍照的取景页进入。
3. 每次DMA提交前核对实际条缓冲全部12800像素并记录CRC，随后等待完成。主机逐条核对六个窗口、颜色和独立CRC，合计每屏76800像素。红、绿、蓝、黑、白及最后白色均通过，日志见outputs/lcd-diagnostic/serial.log和summary.json。
4. 固件重新构建并通过USB烧录，写入哈希校验通过；纯色保持中拍照p和录像r被拒绝。未格式化或增删TF文件。

## 人工观察及归因

用户已确认两项对照：

| 对照 | 面板观察 |
|---|---|
| SPI配置降至20MHz，保持纯白 | 黄色横线仍位于物理左上角，形状不变 |
| 20MHz下切换180度方向，再全屏写白色 | 黄色横线仍位于物理左上角，形状不变，未移动到右下角 |

旋转对照通过六条窗口、全部76800像素及CRC校验，reversed=1、SPI配置20MHz、全部DMA完成。日志见outputs/lcd-diagnostic-rotated/serial.log和summary.json。

综合判断：较高把握属于面板侧固定区域的蓝色显示通路异常，偏向LCD面板、局部驱动或连接问题。LVGL/相机不参与纯色；实际发送缓冲没有黑/黄像素；降速不能消除；坐标反转后异常仍固定物理位置，因此不支持菜单绘制或源数据坐标错误的解释。

这些测试不能精确判断是玻璃面板、驱动芯片、模组连接还是排线，也不能替代示波器/GRAM读回或替换模组对照。特定面板的驱动初始化兼容性尚未用厂商初始化参数做对照，因此这里不作百分之百的元件损坏断言。

后续应断电检查并重新插接LCD排线/连接器，再用同型号已知良好LCD模组替换对照。只有固定蓝色分量异常时，先做面板侧排查的价值高于继续修改LVGL布局。

## 恢复正常运行

对照结束后恢复60MHz配置，重新构建烧录；启动自动使用正常横屏mirror并关闭纯色保持。诊断命令保留供后续维护，默认运行仍为相机取景。恢复构建、烧录及启动日志在outputs/lcd-diagnostic/restored-*。本次未格式化或增删TF文件。
